# Training, registration, scheduling and video update

September 29, 2026. Implemented locally; this is not production or app-store sign-off.

## How to use

1. **Mobile → More → Training:** coaches/staff create a reusable plan, select 1–12 exercises in order, add notes, then assign to 1–30 players for 1–12 weeks with an explicit local due time and IANA time zone. Existing 360-exercise limit, roster authorization, duplicate guards, DST validation and immutable assignment snapshots apply. Edit, archive, restore and cancel remain available.
2. **Web → Operations → Registration rules & seasons:** set optional inclusive minimum/maximum ages, opening/closing instants, active-family-membership requirement and closed status. Dates include a time zone; closing is exclusive. Rules cover registration and waitlist joining, and are checked again when accepting an offer. They use the current, editable profile age, not verified birth dates or a season-age cutoff. Staff configure rules explicitly; the decorative age-range text is not parsed as a policy.
3. **Season rollover:** prepare a copy, name the season/program and confirm. It copies the program and current form into a closed draft, resets registration dates, and closes the original to new registrations. Old enrollments, schedules, payments, waivers and waitlist history stay in place. It does not auto-enroll, re-sign waivers, charge families, move waitlists, or change existing assignments. Review the draft's rules and open it when ready. Duplicate copies from the same source into the same season are rejected. This is a per-program workflow, not a bulk club-wide migration.
4. **Web → Schedule:** weekly practice batches can omit comma-separated local dates. The count represents the original weekly window; skipped weeks are not replaced. Saved occurrences share a series ID and can still be individually edited/cancelled. The tournament preview supports one or two home/away round-robin rounds, 1–4 sessions per team per day, existing rest requirements, court and team blackouts, and all conflict guards. Existing practices count against the daily session limit. Preview must be complete and current before publishing. This remains a bounded greedy scheduler, not a global optimizer; arbitrary recurrence rules and “edit this and following” are not included.
5. **Mobile → More → Video:** select the destination team before recording/picking a clip. A single unfinished draft per account/server is copied into private app storage and recovered when returning to the screen, including after reopening the app. Retry explicitly; keep the screen open during transfer. Uploads time out after two minutes and can be paused; retries resend the whole file, not byte ranges. A stable upload key plus server content/destination checks prevents duplicate files after lost responses. Retrying clip creation with the same uploaded file reuses its team clip. The browser also retries uploads with stable keys while the selected file remains in memory. Discard removes the phone draft, not a server file already accepted.
6. **Mobile video review:** approximate 0.1-second and one-second steps, slow playback, start/end loops, timestamped notes, two-point lines and undo. Starting annotations stops the loop. Frame-accurate seeking, transcoding, multi-draft/background transfer and cloud storage remain outstanding. Device codec support and storage behavior require physical-phone tests.

Existing tests cover family isolation, staff document permissions, account escalation, password/session secrecy, signed payment amounts, capacity/inventory races and failed mutation rollback.
- New domain tests cover age boundaries, membership/window rules, waitlist enforcement, staff-only administration, preserved season history/forms, duplicate rollover, skipped dates across DST, and daily/rest/home-away tournament constraints.
- Web production build and Android/iOS JavaScript exports pass. These are not signed device builds.
- Browser checks: default eligibility rules save successfully; season-copy fields open/cancel; two-game home/away preview schedules at 09:00 and 11:00 with one-hour rest. The preview was not published. Schedule modal takes focus, Shift-Tab/Tab wrap inside, Escape closes it and restores the opener. Phone-width schedule has no horizontal page overflow and all buttons have accessible names.
- Accessibility fixes: main dialogs trap/restore keyboard focus; closed mobile navigation is hidden from keyboard/screen-reader access; navigation exposes its expanded state and a close control. Native new controls have labels, disabled/selected state and 48px targets. Screen-reader and hardware audits are still required.
- Security hardening: API responses use no-store caching, pages deny framing, and a limited CSP blocks object embeds and foreign base URLs. This is not a full CSP or a penetration test. The server still accepts bounded uploads in memory; production scanning, resource controls and cloud storage remain launch work.
